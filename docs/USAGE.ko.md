# 사용 가이드

[English](USAGE.md) · [README](../README.ko.md)

## 설치와 업데이트

[GitHub Releases](https://github.com/HanChangHun/ScreenBrightController/releases/latest)에서 `ScreenBrightController_<버전>_x64-setup.exe`를 내려받습니다. Windows x64와 Microsoft Edge WebView2 Runtime이 필요합니다.

- 관리자 권한 없이 현재 사용자에게 설치합니다.
- 시작 메뉴·바탕 화면 바로가기와 Windows 설치된 앱 목록에 등록합니다.
- 기본 실행 파일은 `%LOCALAPPDATA%\Screen Bright Controller\ScreenBrightController.exe`입니다.
- WebView2가 없을 때만 내려받습니다.
- 코드 서명 인증서가 없어 게시자 또는 SmartScreen 경고가 나올 수 있습니다.
- 이 저장소의 배포 파일만 사용하고, 필요하면 함께 제공되는 `SHA256SUMS.txt`와 비교하세요.

설치만으로 자동실행이나 디밍이 켜지지 않습니다. 시작 메뉴에서 실행한 뒤 트레이 아이콘을 왼쪽 클릭하면 조절 창이 열립니다. 별도 메인 창과 Open app 동작은 없습니다. 일반 실행·로그인·중복 실행은 조절 창을 열지 않으며, 디밍이나 밝기 복원을 자동으로 수행하지 않습니다.

업데이트는 새 버전 설치 파일을 직접 실행하는 수동 방식입니다. 업데이트·제거 전에는 트레이 메뉴의 **Restore and quit**으로 종료하세요. 설치 프로그램은 실행 중인 실행 파일을 교체·제거하지 않으며, 앱이나 복원 감시 프로세스를 강제 종료하지 않습니다.

개발 폴더 `dist`의 구형 포터블 실행 파일은 설치본에 필요하지 않습니다. 설치본과 함께 실행하거나 감마 조절 프로그램 두 개를 동시에 실행하지 마세요.

## 조작

변경은 즉시 적용되며 적용 버튼이나 확인 팝업이 없습니다.

| 동작 | 결과 |
| --- | --- |
| 트레이 아이콘 왼쪽 클릭 | 조절 창 표시·숨기기 |
| 슬라이더 드래그·숫자 입력 | 1 단위 조절 |
| 슬라이더 방향키·마우스 휠 | ±5 조절 |
| 슬라이더에서 Home / End | 0 / 90 요청 |
| − 클릭·Escape | 창을 숨기고 디밍 유지 |
| Restore original | 저장된 원래 감마 복원 |
| 트레이 아이콘 우클릭 | Restore·Restore and quit 메뉴 |
| ⚙ 설정 열기 | Windows 시작 시 실행 설정 |

조절 창은 포커스를 잃어도 유지됩니다. 창을 닫거나 숨기는 동작은 앱 종료와 다릅니다.

## 창 이동과 크기 조절

제목 또는 헤더의 빈 공간을 드래그해 창을 이동합니다. 버튼·입력 필드에서는 창 이동을 시작하지 않습니다. 테두리와 네 모서리에서 크기를 조절하며, 오른쪽 아래에 작은 크기 조절 표시가 있습니다.

- 기본 크기는 논리 픽셀 430×340, 최소 크기는 430×260입니다.
- 설정·상세 정보나 모니터가 많으면 내부에서 스크롤합니다.
- 위치·크기는 현재 실행 중인 세션에서만 숨기기·다시 열기 후 유지됩니다.
- 다시 열 때 기본 크기나 트레이 위치로 초기화하지 않습니다.
- 재시작하면 트레이 근처에서 새 창을 열며, 위치·크기는 저장하지 않습니다.
- 작업 영역·DPI 변경 시 기존 위치·크기를 화면 안으로 보정합니다.
- 모니터가 제거되면 가까운 남은 작업 영역으로 창을 옮깁니다.
- 작업 영역이 아주 작으면 최소 크기보다 작업 영역을 우선합니다.

창 이동·크기 조절은 디밍이나 자동실행 설정을 변경하지 않습니다.

## Windows 시작 시 실행

⚙ 설정에서 **Start with Windows**를 켭니다. 기본값은 꺼짐이며, 관리자 권한 없이 직접 변경할 때만 등록합니다. 로그인 시에는 트레이에만 실행되고 조절 창 열기·디밍·밝기 복원을 수행하지 않습니다.

체크박스는 현재 사용자의 실제 Windows Run 등록을 읽습니다. 변경 결과를 다시 읽어 검증하며, 오류가 나면 이전 등록 복구를 시도하고 확인된 상태를 표시합니다. 상태를 알 수 없으면 체크박스를 비활성화합니다.

실행 파일은 고정 위치에 두세요. 이동·이름 변경 후 다시 켜면 경로가 갱신됩니다. Windows 시작 앱·작업 관리자 또는 조직 정책이 로그인 실행을 별도로 차단할 수 있습니다. 체크박스는 이 앱의 Run 등록을 표시하며 외부 정책을 우회하지 않습니다.

## 복원과 제한 사항

**0**은 원래 감마, **90**은 원래 감마 값의 10%를 요청합니다. 모니터 백라이트 밝기 10%를 뜻하지 않습니다. 화면 오버레이나 DDC/CI 대신 GPU 감마를 조절합니다.

Windows·드라이버가 요청을 거부하거나 읽기 검증에 실패하면 조작을 잠그고 대기 중인 요청을 버립니다. 잠긴 동안 숫자는 적용이 확인된 값이 아니라 요청한 값입니다.

1. 오류 안내의 **Restore**로 복원합니다.
2. 복원에 성공한 뒤 더 낮은 값을 직접 시도합니다.
3. 필요하면 **Details**에서 API 반환과 읽기 검증 결과를 구분해 확인합니다.

자동 재시도·임의 범위 제한·드라이버 제한 우회는 하지 않습니다. 복원이 실패하면 조작 잠금과 복원 버튼을 유지합니다. 상태 조회가 실패해도 조회가 회복될 때까지 새 요청을 보내지 않습니다. 종료 중 복원이 실패하면 앱을 열어 둔 채 Restore를 다시 시도할 수 있습니다.

HDR·ICC 프로필·Night Light·드라이버 동작·GPU/OS 초기화가 감마 조절에 영향을 줄 수 있습니다. 하드웨어 커서는 화면과 다르게 보일 수 있습니다. 전체 요청 범위의 지원 여부는 환경에 따라 다르며, API 성공이나 읽기 검증만으로 실제 화면 효과를 확인할 수는 없습니다. 네이티브 호출이 멈추거나 OS 또는 두 프로세스가 모두 실패하면 복원을 보장할 수 없습니다.

직접 확인해야 하는 동작은 [수동 확인](../MANUAL_TESTS.md)에 있습니다.

## 빌드와 검증

빌드 환경·전체 테스트 명령·결과 파일·배포 절차는 [배포 가이드](RELEASING.md)에 있습니다. 검증에는 Python 3.11 이상이 필요합니다. 소스 패키지는 `screen-bright-controller`와 `screen-bright-controller-tray`이며, 별도 진단용 타깃은 `cargo build --release --locked --bin screen-bright-controller-cli`로 빌드합니다.

실행 파일 검증 스크립트는 `--exe "설치된 실행 파일 경로"`와 `--evidence-dir "검증 결과 폴더"`를 받습니다. 구형 `dist` 실행 파일은 다시 만들지 않으며, 실제 감마 진단은 읽기 전용이고 watchdog 장애 검증은 메모리만 사용합니다. 실행 파일과 로컬 진단 자료는 소스 저장소에 포함하지 않습니다.
